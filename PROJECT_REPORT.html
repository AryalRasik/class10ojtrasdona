Abstract

The Library Management System (LMS) is a web-based application developed for Shree Saraswati Secondary School to digitize and streamline library operations. The system replaces traditional manual book-keeping with a modern, responsive web platform that supports book cataloging, borrowing management, digital resource access, user authentication, and administrative reporting.

Built using HTML5, CSS3, and vanilla JavaScript as a Single Page Application (SPA) with hash-based routing, the system operates entirely in the browser with a clean separation of concerns. The backend is powered by Supabase, a cloud-hosted PostgreSQL database with real-time capabilities, providing authentication, data storage, and row-level security. The application follows a Progressive Web App (PWA) architecture with a Service Worker for offline caching and a Web App Manifest for installability on mobile devices.

The system supports four distinct user roles — Student, Teacher, Librarian, and Admin — each with role-based access control and configurable permissions. Key features include a searchable book catalog with 100+ CDC curriculum textbooks across Grades 1-10, borrow request workflow (request → approve → pickup → return), reservation queue management, fine calculation for overdue returns, digital library with PDF access, study materials management, announcements, events calendar, notifications, audit logs, and a responsive admin dashboard with reports.

The system is deployed on Vercel as a static web application, ensuring fast load times, global CDN availability, and zero server maintenance. All data is persisted in Supabase cloud with full backup and recovery. The application has been tested across multiple browsers (Chrome, Firefox, Edge) and device types (desktop, tablet, mobile) to ensure cross-platform compatibility.

Keywords: Library Management System, Web Application, SPA, JavaScript, Supabase, PWA, School Library, Digital Library, Borrow Management, Role-Based Access Control

Preface (Frontend)

The frontend of this Library Management System represents the visible face of the project — the part that students, teachers, librarians, and administrators interact with directly. It was designed from the very beginning with a clear philosophy: to build a fast, beautiful, and responsive user interface using minimal, understandable technology rather than heavy frameworks that would be difficult for school developers to maintain.

The frontend is built as a Single Page Application (SPA) using pure HTML5, CSS3, and vanilla JavaScript. No React, Vue, or Angular is used. Instead, a custom hash-based router (router.js) was written in about 130 lines to handle navigation between more than 30 distinct pages — from the book catalog and book detail views, to the digital library, study materials, announcements, and the five administrative panels. Each page is an independent module (js/pages/*.js) that exposes a render() method, making the codebase easy to understand, test, and extend page by page.

Special attention was given to the user experience. The interface supports dark and light themes through CSS custom properties defined in css/variables.css, adapting instantly with a single toggle. The design is fully responsive, with a desktop sidebar, a mobile bottom navigation bar, and a floating action button, ensuring a smooth experience from a 320px phone screen to a 4K desktop display. The custom component library — toast notifications, modal dialogs, star ratings, book covers, QR codes, and bar codes — was built from scratch to keep the application lightweight and coherent, with no external CSS or JS frameworks.

The frontend also embraces Progressive Web App (PWA) technology. A service worker (sw.js) implements a network-first caching strategy so that the application shell and Google Fonts remain available even when internet connectivity is lost, and a web app manifest (manifest.json) allows students to install the library on their mobile home screens like a native application.

State management and data access are handled through a well-organized client architecture: state.js maintains the global application state (user session, books, borrow requests, notifications), api.js wraps all Supabase database operations, and utils.js provides shared utilities such as HTML escaping, date formatting, debouncing, and an icon library of over 50 inline SVGs. This modular separation of concerns — routing, view, state, and data access — is the core design decision that keeps the entire frontend organized and maintainable.

Preface (Backend)

The backend of this Library Management System handles the unseen but critical work: storing data securely, authenticating users, and enforcing rules about who may do what. The primary decision behind the backend was to leverage a cloud-hosted database platform (Supabase) rather than building and maintaining a physical server — a choice that keeps the system cost-free, always available, and automatically secure.

The heart of the backend is a PostgreSQL database managed through Supabase. Its schema, defined in supabase/schema.sql, consists of 24 interrelated tables: profiles (extending the built-in authentication users), books, categories, borrow_requests, reservations, notifications, announcements, events, favorites, recently_viewed, reviews, digital_books, study_materials, settings, achievements, login_history, activity_logs, audit_logs, fine_payments, book_imports, feedback, calendar_events, faqs, contact_messages, and sessions. Every table is indexed on its most queried columns and properly linked through foreign keys to guarantee data integrity.

Authentication is handled by Supabase Auth, which manages user sign-up, sign-in, sessions, and JSON Web Tokens out of the box. A database trigger automatically creates a corresponding profile record whenever a new user registers, capturing the user's name, email, and role. Four distinct roles — Student, Teacher, Librarian, and Admin — are enforced through Row Level Security (RLS) policies spanning approximately 250 lines, ensuring that, for example, a student can only ever see and modify their own borrow requests and notifications, while only admins and librarians can approve borrows, manage books, or view audit logs.

A local development server (server.js) was also written using Express.js as an alternative backend for offline testing. It implements a complete security stack: bcrypt password hashing, JWT access and refresh tokens, CSRF protection, rate limiting, account lockout after repeated failed login attempts, input validation, Helmet security headers, and activity/audit logging. It serves the static frontend files and exposes a REST API under /api/.

Finally, the database is pre-seeded with curriculum content — 100+ CDC textbooks across Grades 1-10, sample users for each role, and starter study materials — through supabase/seed.js. The combination of a well-normalized schema, strict row-level security, and cloud hosting means the school receives a backend that is reliable, backup-protected, and requires no dedicated IT staff to operate.

1. Introduction

1.1 Problem Statement

Shree Saraswati Secondary School, located in Changunarayan-08, Sudal, Bhaktapur, serves over 600 students from Grade 1 to Grade 10. The school library maintains a collection of 100+ CDC curriculum textbooks, reference books, and supplementary reading materials across multiple subjects including Nepali, English, Mathematics, Science, Social Studies, and Computer Science.

The current library management system relies entirely on manual processes:

  • Manual Record Keeping: Book issuing and returning is tracked using handwritten registers, making it prone to errors, misplacement, and damage.
  • No Search Capability: Students and teachers must physically browse shelves or ask the librarian to find a specific book, consuming valuable time.
  • Overdue Tracking: Tracking overdue books and calculating fines is a tedious manual process often neglected due to workload.
  • No Digital Resources: The school has no centralized platform to share digital textbooks, study materials, PDFs, or online resources with students.
  • Communication Gap: Library announcements, new arrivals, events, and schedule changes are communicated through notice boards, which students frequently miss.
  • No Analytics: The librarian has no visibility into borrowing trends, popular books, overdue statistics, or usage patterns.
  • Data Loss Risk: Physical registers can be damaged, lost, or tampered with, leading to permanent data loss.

These challenges result in inefficient library operations, reduced book accessibility, poor resource utilization, and a degraded user experience for both students and library staff.

1.2 Proposed Solution

To address the above problems, we propose a Web-Based Library Management System — a modern, responsive, single-page web application that digitizes all library operations. The system provides:

  • A searchable online catalog where students can browse, search, and filter books by title, author, category, grade, subject, and availability.
  • A digital borrowing workflow with request submission, librarian approval, pickup tracking, return processing, and automatic fine calculation.
  • A digital library providing direct PDF access to textbooks and study materials.
  • Role-based access control for Students, Teachers, Librarians, and Admins with configurable permissions and borrow limits.
  • Real-time notifications for borrow approvals, due reminders, overdue alerts, and library announcements.
  • An admin dashboard with borrowing statistics, popular books, overdue reports, and audit logs.
  • A Progressive Web App (PWA) that can be installed on mobile devices and works offline via service worker caching.

1.3 Aim of the Project

The aim of this project is to develop a comprehensive, web-based library management system for Shree Saraswati Secondary School that automates library operations, enhances resource accessibility for students and teachers, and provides the library administration with powerful tools for catalog management, borrowing oversight, and data-driven decision making.

1.4 Objectives

The specific objectives of this project are:

  1. To design and develop a responsive web application that serves as a centralized platform for all library operations.
  2. To implement a secure user authentication system with role-based access control for Students, Teachers, Librarians, and Admins.
  3. To create a searchable book catalog containing 100+ CDC curriculum textbooks with advanced filtering capabilities.
  4. To develop a complete book borrowing lifecycle management system including request, approval, pickup, return, renewal, and fine calculation.
  5. To provide a digital library section for accessing PDF textbooks and study materials online.

1.5 Rationale

The rationale behind choosing this project stems from the practical needs of the school library. Manual library management is inefficient, error-prone, and fails to leverage the potential of modern technology. A web-based system eliminates paper records, reduces human errors, enables instant book searching, automates fine calculations, and provides data analytics — all accessible from any device with a web browser.

Furthermore, with the increasing adoption of digital learning in Nepal's education sector, especially after the COVID-19 pandemic, there is a growing need for digital library resources. This system bridges the gap between physical and digital library management, providing students with 24/7 access to book catalogs and digital resources, thereby promoting a culture of reading and self-directed learning.

The use of modern web technologies (HTML5, CSS3, JavaScript) with a cloud backend (Supabase) and static hosting (Vercel) ensures the system is cost-effective, scalable, and requires minimal maintenance — making it ideal for a school environment with limited IT resources.

3.2 Router (router.js) — Hash-Based SPA Routing

The router uses window.location.hash to manage navigation without page reloads. It supports dynamic route parameters (e.g., /book/:id), route guards for authentication, and page transition animations.

js/router.js
const Router = {
    routes: [],
    currentRoute: null,
    _beforeNavigateCallbacks: [],

    add(path, handler) {
        this.routes.push({ path, handler });
    },

    beforeNavigate(callback) {
        if (typeof callback === 'function') {
            this._beforeNavigateCallbacks.push(callback);
        }
    },

    init() {
        window.addEventListener('hashchange', () => this.resolve());
        this.resolve();
    },

    resolve() {
        const hash = window.location.hash || '#/';
        const full = hash.substring(1);
        const [pathPart, queryPart] = full.split('?');
        const query = {};
        if (queryPart) new URLSearchParams(queryPart).forEach((v, k) => {
            query[k] = v;
        });

        let matched = null;
        let params = { ...query };

        for (const route of this.routes) {
            const routeSegs = route.path.split('/');
            const pathSegs = pathPart.split('/');
            if (routeSegs.length !== pathSegs.length) continue;
            let ok = true;
            const p = { ...query };
            for (let i = 0; i < routeSegs.length; i++) {
                if (routeSegs[i].startsWith(':')) {
                    p[routeSegs[i].slice(1)] = decodeURIComponent(pathSegs[i]);
                } else if (routeSegs[i] !== pathSegs[i]) {
                    ok = false;
                    break;
                }
            }
            if (ok) { matched = route; params = p; break; }
        }

        if (!matched) {
            matched = { handler: {
                render: () => '<div class="error-page"><h2>404</h2></div>',
                afterRender: () => {}
            }};
        }

        for (const cb of this._beforeNavigateCallbacks) {
            if (cb(pathPart) === false) return;
        }

        this.currentRoute = matched;
        this.render(matched.handler, params);
    },

    async render(handler, params) {
        const container = document.getElementById('pageContent');
        if (!container) return;
        container.classList.add('transitioning');
        setTimeout(async () => {
            const html = await handler.render(params);
            container.innerHTML = html;
            container.classList.remove('transitioning');
            if (handler.afterRender) await handler.afterRender(params);
            this.bindLinks();

            Toast.success('Account created! Check email to verify.');
        } else {

            if (storedUsers.find(u => u.email === email)) {
                Toast.error('Email already registered');
                return;

                createdAt: new Date().toISOString() };
            storedUsers.push(newUser);

    getPasswordStrength(password) {
        let score = 0;
        if (password.length >= 8) score++;
        if (/[A-Z]/.test(password)) score++;
        if (/[a-z]/.test(password)) score++;
        if (/[0-9]/.test(password)) score++;
        if (/[^A-Za-z0-9]/.test(password)) score++;
        if (score <= 2) return { level: 'weak', color: 'red' };
        if (score <= 4) return { level: 'medium', color: 'orange' };
        return { level: 'strong', color: 'green' };
    }

const Utils = {

3.10 Service Worker (sw.js) — Offline Support

The service worker implements a network-first strategy: it always tries to fetch from the network first (to get updated content), and falls back to cached content when offline. Google Fonts are cached using a cache-first strategy for performance.

sw.js
const CACHE_NAME = 'saraswati-library-v4';
const ASSETS = [
    './',
    './css/variables.css',
    './css/main.css',
    './css/animations.css',
    './css/components.css',
    './css/pages.css',
    './css/responsive.css'
];

self.addEventListener('install', (e) => {
    e.waitUntil(
        caches.open(CACHE_NAME)
            .then(cache => cache.addAll(ASSETS))
            .then(() => self.skipWaiting())
    );
});

self.addEventListener('activate', (e) => {
    e.waitUntil(
        caches.keys()
            .then(keys => Promise.all(
                keys.filter(k => k !== CACHE_NAME)
                    .map(k => caches.delete(k))
            ))
            .then(() => self.clients.claim())
    );
});

self.addEventListener('fetch', (e) => {
    if (e.request.method !== 'GET') return;

    // Cache-first for Google Fonts
    if (e.request.url.includes('fonts.googleapis.com') ||
        e.request.url.includes('fonts.gstatic.com')) {
        e.respondWith(
            caches.match(e.request).then(r => r ||
                fetch(e.request).then(resp => {
                    const clone = resp.clone();
                    caches.open(CACHE_NAME)
                        .then(cache => cache.put(e.request, clone));
                    return resp;
                })
            )
        );
        return;
    }

    // Network-first for everything else
    e.respondWith(
        fetch(e.request).then(resp => {
            if (resp && resp.ok) {
                const clone = resp.clone();
                caches.open(CACHE_NAME)
                    .then(cache => cache.put(e.request, clone));
            }
            return resp;
        }).catch(() =>
            caches.match(e.request)
                .then(r => r || caches.match('./'))
        )
    );
});

    show({ title = '', content = '', buttons = [], size = 'md' }) {
        if (!this.container) this.init();
        let btnsHtml = buttons.map(b =>
            `<button class="btn ${b.class || 'btn-secondary'}"
                >${Utils.escapeHtml(b.label)}</button>`
        ).join('');

        this.container.innerHTML = `
            <div class="modal-backdrop"></div>
            <div class="modal">
                <div class="modal-header">
                    <h3>${Utils.escapeHtml(title)}</h3>
                    <button class="modal-close">X</button>
                </div>
                <div class="modal-body">${content}</div>
                ${buttons.length ?
                    `<div class="modal-footer">${btnsHtml}</div>` : ''}
            </div>
        `;
        this.container.classList.add('active');

        this.container.querySelector('.modal-close')
            .addEventListener('click', () => this.hide());
        this.container.querySelector('.modal-backdrop')
            .addEventListener('click', () => this.hide());

        const actionBtns = this.container
            .querySelectorAll('.modal-action-btn');
        actionBtns.forEach((btn, i) => {
            btn.addEventListener('click', () => {
                if (buttons[i] && buttons[i].onClick)
                    buttons[i].onClick();
                this.hide();
            });
        });
    },

    hide() {
        if (this.container) this.container.classList.remove('active');
    },

    confirm(title, message, onConfirm) {
        this.show({
            title, content: `<p>${message}</p>`,
            buttons: [
                { label: 'Cancel', class: 'btn-secondary' },
                { label: 'Confirm', class: 'btn-primary',
                  onClick: onConfirm }
            ]
        });
    }
};

6. Conclusion

The Library Management System developed for Shree Saraswati Secondary School successfully achieves all the stated objectives. The web-based application provides a comprehensive, user-friendly platform for managing library operations — from book cataloging and searching to borrowing lifecycle management, digital resource access, and administrative reporting.

The system eliminates the inefficiencies of manual library management by providing instant book search, automated borrow tracking, fine calculation, and real-time notifications. The role-based access control ensures that students, teachers, librarians, and administrators each have appropriate levels of access and functionality.

The use of modern web technologies (HTML5, CSS3, vanilla JavaScript) with a cloud backend (Supabase) and static hosting (Vercel) has resulted in a system that is:

  • Fast: Static file serving with CDN ensures sub-second load times.
  • Reliable: Supabase provides 99.9% uptime with automatic backups.
  • Scalable: Can easily handle more books, users, and features.
  • Cost-free: No hosting costs with Vercel free tier and Supabase free tier.
  • Maintainable: Clean modular code structure makes updates easy.

The PWA features (Service Worker, Web App Manifest) enable students to install the application on their mobile devices and access cached content offline, making it particularly suitable for the school environment where internet connectivity may be intermittent.

6.1 Limitations

  • The system does not yet support email-based password reset (Supabase email confirmation required).
  • Offline mode is limited to cached pages; new data requires internet connectivity.
  • The system currently does not integrate with the school's Student Information System (SIS).

6.2 Future Scope

  • Integration with the school's SIS for automatic student enrollment.
  • Email and SMS notifications for overdue books and events.
  • Barcode/QR code scanning for quick book issuing and returning.
  • Book recommendation engine based on reading history and preferences.
  • Multi-language support (Nepali and English interfaces).
  • Advanced analytics dashboard with exportable PDF/Excel reports.

In conclusion, this project has been a valuable learning experience in full-stack web development, database design, user interface development, and software engineering practices. The skills and knowledge gained through this project will serve as a strong foundation for future software development endeavors.
